# Dashboard Royale assistant

A local AI chatbot for the Dashboard Royale dashboard. It answers questions about the six challenge questions (Q1–Q6) using only the dashboard's verified findings, with a model that runs on your own machine through [Ollama](https://ollama.com). No paid or cloud APIs, and no vector database.

## How it works

```
Dashboard (:5179)  ──/api/assistant/chat──>  Assistant service (FastAPI, :8100)  ──>  Ollama (:11434, qwen2.5:3b)
  floating "AI" button                          1. find relevant findings in knowledge_base.json
  and chat panel                                2. send them to the model as its only context
                                                3. flag any number in the answer that isn't in that context
```

- **Knowledge base:** `knowledge_base.json` is generated by `build_knowledge.py` from the dashboard's own data (`casinoguard/public/data/*.json`) and from the verified claims on the Methodology page. No figure is typed in by hand.
- **Retrieval:** keyword scoring over about 20 entries. Naming a question, such as "Q3", always includes that question's main finding.
- **Grounding:**
  - The model is told to answer only from the retrieved findings and to copy numbers exactly.
  - If the findings don't cover a question, it says so.
  - The service checks every number in an answer against the findings it was given. The chat panel shows a warning for any number that doesn't match.
- **Sources:** each answer lists the questions it drew on, linked to their dashboard pages.

## Run it

Ollama runs as a background service (installed with Homebrew):

```bash
brew services start ollama
```

```bash
ollama pull qwen2.5:3b
```

Start the assistant service, from `Dashboard-Royale/assistant`:

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

```bash
.venv/bin/python -m uvicorn app:app --port 8100
```

Then start the dashboard (`cd Dashboard-Royale/casinoguard && npm run dev`). Its dev server forwards `/api/assistant` to port 8100. Open http://localhost:5179 and click the **AI** button in the bottom-right corner.

Health check: http://localhost:8100/api/assistant/health

## Configuration (optional)

| Variable | Default |
|---|---|
| `OLLAMA_URL` | `http://127.0.0.1:11434` |
| `OLLAMA_MODEL` | `qwen2.5:3b` |
| `OLLAMA_TIMEOUT_SECONDS` | `120` |

## After the dashboard data changes

Regenerate the knowledge base so the assistant's figures match the dashboard, then restart the service:

```bash
python3 Dashboard-Royale/assistant/build_knowledge.py
```

## Tests

```bash
.venv/bin/pip install -r requirements-dev.txt && .venv/bin/python -m pytest -q tests
```

## Limits

- A 3-billion-parameter model can phrase things awkwardly or leave details out. The number check catches invented figures, but not every omission.
- The published static build of the dashboard (for example GitHub Pages) has no assistant service. There, the panel explains that the service isn't reachable.
